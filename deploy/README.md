## S3-03 账户与访问控制

先按上节执行迁移（新增 `002_auth.sql`），再启动 API。前端运行 `npm run dev` 后可在 `http://127.0.0.1:5173` 注册、登录、查看当前账户和退出。注册不自动登录；注册参数不能指定角色。账户持久保存在 PostgreSQL，密码采用独立随机盐的 scrypt（N=32768、r=8、p=3），参考 [OWASP 密码存储指引](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)。密码首轮接受 8–128 个字符，登录不回显密码验证错误内容。

会话是数据库中的可撤销记录，浏览器只持有随机 HttpOnly、SameSite=Strict Cookie；数据库仅存令牌哈希。首轮服务端有效期为 8 小时（`AUTH_SESSION_SECONDS=28800`），不设置持久 Cookie 或免密码登录；浏览器恢复会话可能保留会话 Cookie，因此应使用“退出登录”明确撤销。认证后变更请求须携带 `/auth/login` 或 `/auth/me` 返回的 `csrf_token`，通过 `X-CSRF-Token` 请求头提交。前端只在内存保存该值，不使用 localStorage。

本地 HTTP 回环环境默认 `AUTH_COOKIE_SECURE=false`；允许局域网访问前须在部署验收中配置 HTTPS、设置为 `true` 并核对 `AUTH_ALLOWED_ORIGINS`，不能把密码通过不受控网络明文传输。API 明确禁用 Uvicorn 代理头信任，来源限速不使用用户可伪造的 `X-Forwarded-For`。Vite 开发代理后的访问会被视为同一来源，源级限速是共享的；账号级限速仍独立生效。

已批准登录限速为每账号 15 分钟内 5 次失败、每来源 15 分钟内 20 次失败，各暂停 15 分钟；注册首轮默认每来源 15 分钟 20 次请求，达到后暂停 15 分钟。示例配置提供阈值、窗口及暂停秒数，可在本机调整。限速状态持久化于 PostgreSQL，重启 API 不会清零。邮箱验证和密码找回按 MVP 决策暂未实现。

部署者在交互终端使用下列入口创建管理员，密码由隐藏提示读取，不接受命令行密码参数；同名账户不会被自动提升权限。禁用账户会撤销其现有会话。最终交付时再创建实际管理员账户。

```powershell
docker compose --env-file .env.example run --rm --no-deps api python -m app.admin create-admin --email admin@example.com
docker compose --env-file .env.example run --rm --no-deps api python -m app.admin disable-user --email admin@example.com
```

认证接口为 `/auth/register`、`/auth/login`、`/auth/me`、`/auth/logout`。`GET /tasks/{id}` 仅提供任务所有者的必要元数据；`GET /admin/tasks` 仅向管理员提供分页元数据。所有者可通过 `POST /tasks/{id}/consents` 授予指定 `purpose` 和 `access_scope`（`video` 或 `summary`）的授权，使用 `DELETE /tasks/{id}/consents/{consent_id}` 撤销。复用的内容授权检查每次核实任务归属、删除栅栏和当前同意，并记录管理员允许或拒绝访问的审计。本工作包尚无视频/摘要内容传输接口，进行中流式传输的中断验证留在实际内容接口实现时完成。

S3-03 自动化测试仅使用显式指定且以 `_test` 结尾的 PostgreSQL 测试库，不读取真实 `.env`，不调用外部模型。运行方式为在后端环境设置 `TEST_DATABASE_URL` 后执行 `python -m pytest -q`。尚未实现的上传、额度、队列处理和删除执行按实施计划后续工作包推进。


## S3-04 私有媒体导入

产品负责人于 2026-10-29 批准首轮输入收敛为 **MP4/MOV**，视频仅 H.264/AVC，音轨若存在仅 AAC/MP3；WebM 不在 MVP 范围。原因依据 [WebM 官方容器说明](https://www.webmproject.org/docs/container/)：标准 WebM 的 VP8/VP9、Vorbis/Opus 与此前编码白名单冲突。本轮没有扩充编码支持。2 GB 按 2,000,000,000 字节、2 小时按 7200 秒校验，边界值允许，超出则拒绝。

先构建新版 API/Worker 并执行迁移，新增 `003_inputs.sql` 保存临时导入登记及音轨标记。登录后可在页面选择本地文件或 HTTPS 直达链接，并逐视频确认处理授权。`POST /inputs/upload` 接收原始文件字节（非 multipart），通过 `X-Video-Filename` 传入百分号编码的展示文件名、`X-Upload-Authorized: true` 确认授权；`POST /inputs/url` 接收 `{url, rights_confirmed: true}`。两者均需会话和 `X-CSRF-Token`。文件名只用于展示，不能决定存储路径。URL 的查询参数、凭据和原始地址不落入任务、导出或错误信息。

API 先流式暂存至私有 `input-staging` 卷，检查实际容器、全部音视频编码、时长及完整解码，随后写入私有 RustFS bucket 并在事务中登记原片资产和 Queued 任务。只有校验成功才记录排队提交时间；输入失败或客户端中断不创建处理任务，不扣处理机会。成功只表示导入完成；S3-08 的离线 Worker 随后领取任务，真实模型处理仍未启用。

HTTPS 下载仅使用经校验的公网 IP，TLS 证书及 SNI 仍验证原域名；不使用环境代理，不发送用户 Cookie/认证头。首轮只接受标准 443 端口，拒绝链接内用户名密码、内网/回环/保留及过渡地址；最多 3 次跳转且每次重新验证。实际字节数和响应长度均检查，拒绝页面、播放清单、压缩响应及不完整下载。[FFprobe/FFmpeg 官方说明](https://ffmpeg.org/ffprobe-all.html)是媒体探测及协议白名单的依据；本地媒体探测仅允许 file/pipe 协议和 mov 解复用器，不调用网络媒体来源。

首轮实现默认最多 5 个并行导入；上传/下载各默认 1800 秒，探测 30 秒，完整解码 3600 秒。示例配置可调整：上传/下载最大 3600 秒、探测最大 120 秒、解码最大 10800 秒，对象写入另有 1800 秒保护。这些是实现资源保护，不是已验证的容量或 P90 承诺；超时不会静默截断或以成功入队。完整解码在 API 的后台线程执行，视频时长越长，校验等待也可能越长。

导入登记与资产写入支持失败清理；清理失败保留登记供重试，清理与最终入队持有相同登记行锁。活动校验/存储期间续期；失联登记默认 6 小时失效，API 启动后及每 60 秒检查并清理过期暂存/孤立对象。此暂存清理不替代后续 S3-09 的任务删除、告警和 30/90 天保留流程。前端“中止导入”只中断当前请求；若成功提交与中止同时发生，不能据此宣称已取消排队任务。

API 使用 `S3_ENDPOINT_URL`、`S3_ACCESS_KEY`、`S3_SECRET_KEY` 和 `S3_BUCKET` 访问本机私有存储，Compose 只从无模型密钥的环境示例注入开发占位值。对象存储未开放主机端口、未生成公开或签名媒体 URL，也没有调用 Qwen。

真实媒体测试可用专用镜像运行：`docker build --target test -t video-summary-app-test -f backend/Dockerfile backend`（从仓库根目录）。测试镜像单独包含 pytest/httpx 和测试文件，Compose 运行目标固定为 runtime；集成测试仍须显式指定独立 `_test` 数据库。实际 2 GB/2 小时大文件和本机并发容量未在本轮测量，自动化测试使用短合成视频及受控边界输入。


## S3-05 任务、额度与重试

先构建新版容器并执行迁移，新增 `004_task_rules.sql` 的模型超时重试计数。登录后页面显示普通用户额度、恢复倒计时，以及分页任务列表；导入成功、取消或重试后刷新，显示中的倒计时不决定实际操作资格。管理员显示不限处理机会。`GET /quota` 和 `GET /tasks` 返回当前用户数据；`POST /tasks/{id}/cancel`、`POST /tasks/{id}/retry` 需有效会话和 CSRF。重试 JSON 为 `{request_key: UUID字符串}`，请求失败结果未知时须复用相同标识，不能重新生成来重复接受同一意图。

普通用户初始 3 次，仅首次实际开始扣一次。同任务后续重试即使已获退款也不再次扣额；管理员不产生扣额流水。余额低于 3 后按每 6 小时恢复一次计算，后续使用不重置计时，达到 3 时停止；退款不重置仍在进行的恢复计时。服务端在读取额度或相关事务时补算离线/未登录期间已到期的恢复，不依赖浏览器运行计时器。余额、事件流水与任务变更在同一 PostgreSQL 事务中完成，按用户再按任务加锁，并依靠任务级扣额/退款唯一键防止重复。

内部、外部超时/限流/不可用及未知失败按既定规则返还已扣且未返还的机会，余额封顶 3；明确用户输入问题和处理中的主动取消不退款。排队取消不扣额，取消和成功为终态；迟到失败、成功或取消不能覆盖已经提交的终态。并发取消/失败以权威事务先提交的最终分类为准，原因和结果留在任务/尝试及非正文审计记录。

手动和系统调用共用重试规则与计数。滚动窗口采用 `(当前时间－5分钟, 当前时间]`，恰好 5 分钟前的记录退出窗口。前 4 次已接受重试不触发冷却，第 5 次已接受重试触发，冷却阶梯依次为 1/5/15/30 分钟并封顶；冷却期间请求不增加计数、不延长等待。累计接受 20 次后拒绝第 21 次。第 5 次触发冷却后任务仍为 Queued，但内部开始入口必须等冷却结束。取消或成功后不能接受新重试；已接受请求的重复投递只返回当前结果，不重复计数。第 4 次及之后的模型超时重试显示可能产生 API 费用的提示，处理机会不因此再次扣除。

`app.tasks.start_task/fail_task/succeed_task` 是供后续 Worker 使用的内部事务入口，不开放为浏览器 API。开始与终结记录处理尝试和代次；终结写入检查当前代次、活动状态和删除栅栏。成功入口的可信调用方仍须先完成真实输出验证。队列与租约能力见 S3-06；运行时尚未绑定真实处理器，未启用实际处理、自动重试循环或模型调用；处理中取消对实际媒体/模型工作的中断在对应 Worker 工作包接入。完整回归使用假时钟、独立 PostgreSQL schema 和并发线程，不调用真实模型。


## S3-06 持久队列与 Worker 租约

构建新版镜像并执行迁移 `005_queue.sql`，新增 `schedule_events` 调度元数据：原始提交时间、用户/任务排序键、领取 Worker、代次、启动及受阻/越过/恢复事件和关联任务。该记录跟随源任务的 30 天元数据期限，由 S3-09 接入清理；不记录视频、摘要或 URL 正文。用户任务状态仍只有已有五种。

调度按 `(submitted_at, user_id, task_id)` 选择，数据库单一调度临界区保证两个 Worker 不同时突破总并发或重复领取。普通用户最多一个活动任务；管理员受全局并发和 FIFO 约束。只有前方任务因普通用户已有活动任务、且除此之外符合条件时，才允许其他用户任务越过；同用户后续任务不会抢先启动。额度不足、冷却/等待、账户停用等其他原因会保守地阻塞队列，不扩展为一般优先级调度。调度不会使用 `SKIP LOCKED` 偷换顺序。

公平性采用已有排序而非新增年龄优先级：用户活动任务释放后，其最早符合条件任务仍排在更晚提交者之前；记录实际越过和阻塞原因以便检查。此行为已做功能测试，不代表已测出长期饥饿的时间上界或 10–30 人的容量。不可运行的队首需要按原有业务规则解除阻塞，不能用所谓防饥饿策略绕过已批准限制。

首轮全局并发默认 `QUEUE_GLOBAL_CONCURRENCY=1`，可按实际本机测量调整；这不是容量承诺。默认租约 `WORKER_LEASE_SECONDS=120`、心跳 `WORKER_HEARTBEAT_SECONDS=30`，必须为正且心跳小于租约；轮询 `WORKER_POLL_SECONDS=1`。API 和 Worker 注入一致配置。调度领取、首次扣额、活动状态、租约和处理尝试在同一事务提交。

心跳和数据库写入须核对当前 Worker、代次、未过期租约、Processing 状态、账户有效性及未删除标记。`queue.fenced_write` 在同一数据库事务中保护资产登记等写入；外部对象仍须先私有暂存，在登记被拒时由后续处理流程清理，不能把数据库事务误称为跨存储原子提交。过期或缺失租约的活动任务由恢复事务记为内部失败并幂等退款、提高代次，已请求删除的任务按取消规则释放活动名额。旧 Worker 恢复后不能续约或写入。

恢复不会自动重新调用模型：外部请求是否完成可能未知，任务须经过 S3-05 的重试入口重新排队。相同任务不再次扣额，手动和系统重试共用冷却与累计限制。取消或账户停用后，Worker 的下一次检查会向处理器发出停止信号；即使处理器不配合，租约及终态检查仍阻止其继续提交数据库结果。

`worker.run(..., processor=callback)` 是后续 S3-07 和测试使用的内部接入点。处理器通过 `WorkerContext` 检查取消、执行受租约保护的写入，并在实际输出验证完成后显式确认成功；仅返回函数不会被视为总结成功。S3-06 交付时命令行 Worker 只执行恢复；S3-08 已增加显式的离线替身处理模式，见下文。没有公开的开始/成功/失败接口。

任务数据库连接/SQL/锁等待默认受 `TASK_DB_TIMEOUT_SECONDS=5` 保护，不覆盖连接字符串中的测试 schema 配置。`WORKER_SHUTDOWN_SECONDS=5` 为观察到停止后的结算和回调等待预算；已发出的数据库操作可能另外等待自身超时。停止不再领取任务，无法及时结算时交由租约过期恢复。不承诺强制终止任意 Python 线程；不合作的处理器不能占用进程退出，且不能带着旧令牌提交结果。

独立测试使用隔离 PostgreSQL schema、可控时钟、合成处理器及并发 Worker；另有实际子进程被强制结束后的恢复验证。以上验证不包含模型请求、真实视频处理、完整备份恢复或本机负载容量测量。


## S3-07 本地证据预处理与模型适配边界

先构建新版容器并执行 `006_model_calls.sql`。本轮提供 `preprocess.prepare_media`、`model_adapter.ModelAdapter` 和 `processing.prepare_and_analyze`；Worker 的命令行入口仍未绑定端到端处理器，不会自动领取视频或调用模型。真实 Qwen 接入留在 S3-11 获批批次，正式摘要/JSON 成功门槛由 S3-08 接入；没有启用运行时假总结或新增 UI 成功出口。

原片保持完整，不因适配器限制静默分段或截断。每条视频轨按默认约 10 秒间隔采样 JPEG（最长宽度 768），保留实际源 PTS 与轨道编号，统一减去媒体时间原点；每条可用音轨按完整时间范围转换为 16kHz 单声道 PCM WAV，并记录音轨相对视频的起始偏移与结束位置。编码填充及时间原点作明确映射，保留无音轨和抽样限制说明。重采样/混音不是原始音频的逐比特保留，画面抽样也不证明每个事件都被覆盖。尚未执行真实语音识别、真实多模态理解或质量评测。

配置默认 `PREPROCESS_FRAME_INTERVAL_SECONDS=10`、`PREPROCESS_FRAME_WIDTH=768`、`PREPROCESS_TIMEOUT_SECONDS=3600`；允许的实现范围分别为间隔至少 0.1 秒、宽度 16–3840、单阶段超时 1–10800 秒。现有输入仍限 MP4/MOV、H.264、AAC/MP3、2h/2GB；这些参数不是质量阈值或性能保证。验证及提取子进程仅允许本地 file/pipe 协议与 mov 解复用器，取消会终止子进程并清理部分文件。

桥接层通过当前租约读取该任务登记的私有原片，下载时检查实际字节数、长度与取消状态。工作目录位于 `PROCESSING_WORK_DIR` 对应的私有 `worker-processing` 卷；媒体资产表记录受控的 `PROCESSING_WORKSPACE` 键与代次，不保存主机绝对路径。正常退出实际清理后才标记 DELETED；清理失败保留 FAILED 记录。Worker 在恢复时及约每 60 秒清理失联/终结工作目录，跳过当前有效租约的活动目录。这为后续 S3-09 的源任务关联删除保留依据，不替代完整任务删除与保留实现。

模型请求只含必要画面字节、音频流、源相对时间戳、轨道编号、语言、提示版本及局限说明。服务端工作清单中的本地路径不序列化给模型；用户/任务标识、邮箱、原始 URL、展示文件名、访问令牌和存储凭据不属于适配器请求。接口支持 zh/en 并提供 `MODEL_ADAPTER_TIMEOUT_SECONDS=120` 的调用预算（最大 3600 秒）；未来外部传输必须实现真实超时和合作取消，当前接口本身不能强行终止任意阻塞的第三方代码。

离线 `FakeModelAdapter` 仅检查音画证据传递并返回明确标记为 OFFLINE TEST 的合成候选。响应包含来源观察、时间戳、请求标识、模型/适配器版本及用量；检查有限、源内且有序的事件时间，以及观察轨道是否实际提供。此检查只约束接口，不是正式 JSON Schema、事实准确率或模型质量验收。桥接函数单独返回候选后，任务仍为 Processing；S3-08 调用方完成规定输出校验和原子保存后才确认成功。

`model_calls` 仅存任务/尝试关联、版本、请求 ID、用量、分类错误和时间等元数据，随源任务按 30 天规则清理；不存候选正文或完整请求。实际用量或成本未知时为 NULL，不伪造零费用。错误包括超时、限流、外部不可用、输入与内部错误；本机私有存储/已验收原片损坏属于内部失败。失败依既有规则处理额度，适配器不自行循环重试。同一任务代次最多登记一次适配调用，重复入口以 `AlreadyAnalyzed` 拒绝，避免二次调用和破坏已有候选状态。

调用登记的 SUCCEEDED 仅表示本次适配响应已通过接口检查，不表示任务、摘要或导出成功。取消、租约失效或进程异常后可能保留未结算 RUNNING 记录；它表示结果未知，不能据此推断供应商仍在运行、用量为零或不计费，也不能绕过 S3-05 自动重发。

本轮测试使用短合成媒体、离线替身和隔离数据库；另有真实私有 RustFS 下载到预处理/替身的集成验收。没有读取 Qwen Key、调用外部模型或外发真实视频。真实 2 小时/2 GB 处理、模型语义质量、P90、费用和公网媒体回连均未据本轮测试宣称通过。


## S3-08 双语结果与应用闭环

先按顶部顺序构建并迁移，再启动 API/Worker。新增 `007_task_results.sql` 保存中英文结果与处理代次，关联任务/用户。`WORKER_PROCESSOR_MODE=offline`（Compose 默认）让独立 Worker 使用离线替身完成一次预处理/适配调用，提供两个语言候选；`disabled` 只恢复失效任务、不领取新任务。`MODEL_CALLS_ENABLED=false` 保持外部调用关闭，其他处理器模式或开启外部调用会被当前 Worker 拒绝。不能用演示结果判断模型质量或 P90。

输出校验分为页面契约和导出契约。页面需要总览、3–7 条要点、有序章节、关键事件和音画局限；少于三个关键事件时须有局限说明，无事件允许空数组。JSON 1.0 只含 PRD 规定字段，校验字段集合、类型、非空文本、语言、有限且源内有序的时间戳、无路径展示文件名。不增加用户/任务标识、逐字稿、importance 或存储位置。此校验保证结构和必要内容存在，不证明事实或翻译正确，语义质量仍须后续人工基线评测。

`OUTPUT_REPAIR_ATTEMPTS=1` 是首轮可配置实现默认（允许 0 或 1）：只在解析失败时去掉包裹完整 JSON 的代码围栏，再严格校验一次；不补写字段、不丢弃未知字段、不排序事件、不截断视频，也不重新调用模型。仍不合格则内部错误失败、按现有规则退款；无效结果不能下载。双语结果、资产登记、任务/attempt 的成功状态在同一租约检查事务中提交，取消、删除或旧代次均不能迟到发布。

`GET /tasks/{id}/result?language=zh|en` 返回页面和规定导出文档；`GET /tasks/{id}/export?language=zh|en` 在下载时再次校验，以 JSON 附件返回。`GET /tasks/{id}/video` 支持单个字节范围请求，由服务端代理私有原片，每次传输继续前检查当前会话、归属和删除状态，不生成公开存储 URL。以上只向所有者开放，管理员身份不自动授予其他用户内容访问。S3-09 已补齐任务级管理员内容授权和删除运营，见下一节。

结果正文存于本机 PostgreSQL 的 `task_results`；每份导出/页面正文分别登记为 `RESULT_JSON`/`RESULT_DOCUMENT`，资产键为受控的 `db-result/{result_id}/export` 或 `/presentation`。后续 S3-09 清理必须同时删除对应 SQL 正文与资产登记，不能仅删除对象存储。处理工作区沿用 S3-07 的登记与恢复清理。

用户界面提供历史分页、五种状态、排队/实际处理时长和进度条。Processing 为不确定进度，不虚构百分比或精确 ETA；60 分钟视频显示 20 分钟需求目标，未据替身测试宣称达到。重试后的排队时长从本次重试接受时计算，所有保存时间仍为 UTC，显示按浏览器时区转换。成功直接刷新状态；用户可展开结果、切换语言、点击章节/事件时间跳转播放、下载相应 JSON。离线模式在上传前及结果页均明确标识。

管理员元数据页面可按用户 ID 筛选和分组，查看时间、错误、重试、额度及模型用量元数据；不默认展示视频或摘要正文。未知用量/费用继续为 NULL，不表示免费或不计费。

本包验收包含独立的契约/租约/取消/退款/隔离/视频范围读取测试，以及合成 H.264/AAC 短视频通过实际 HTTP 注册登录、上传、私有 RustFS、独立 Worker、双语结果及导出的闭环。仅使用非敏感合成输入，未读取真实密钥、调用外部模型或外发视频。完整删除/保留、真实模型语义与费用、2h/2GB 实际负载和性能目标仍按后续工作包验证。


## S3-09 删除、授权撤销、保留与恢复控制（历史交付/当前旧实现）

先按顶部顺序构建、执行迁移，再启动服务；新增 `008_cleanup.sql` 和 `009_deletion_control.sql`。不需要真实模型密钥。删除控制使用独立的 `deletion-control` 命名卷；API 与 Worker 共享该卷，不能随 PostgreSQL/对象存储旧快照一起回滚。不要使用 `down --volumes` 删除它。

所有者可对任何状态的任务发起 `DELETE /tasks/{id}`，需要有效会话和 CSRF。202 只表示已接受删除：立即设置删除栅栏、使旧租约失效、取消排队/处理中任务并移出历史，不表示已经清除所有数据。排队不扣额，处理中主动删除不退已扣机会。`GET /deletions` 返回独立回执，分别显示在线清理与备份状态；取消、重试、读取/导出和旧 Worker 迟到写入均不能绕过删除控制。

独立 Worker 内的清理线程默认每 `CLEANUP_POLL_SECONDS=5` 秒检查，失败重试默认间隔 `CLEANUP_RETRY_SECONDS=60` 秒。初次清理不算重试；第 4 次自动重试失败（共 5 次失败尝试）或启动后超过 30 分钟仍未完成时持久告警并转人工。长租约和未来重试时间不能延后超时告警；管理员推进也不能重置期限或跳过旧 Worker 安全等待。处理中任务先阻止读写，物理清理必要时等待原租约到期，避免仍在退出的处理器重建文件。

清理枚举原片、音频/帧/工作目录、页面/JSON 正文、缓存、关联评测副本、标注、模型输出和失败案例。私有 S3 删除后检查对象不存在，数据库正文与关联日志实际删除后才确认在线完成。未知资产位置或无法验证的对象保留失败记录，不静默排除。`RESULT_JSON`/`RESULT_DOCUMENT` 必须清理 `task_results` 正文；`PROCESSING_WORKSPACE` 只操作受控 UUID 目录，不接受任意主机路径。评测资料去标识化不豁免源任务删除。

各状态任务从创建起 30 天到期；普通任务日志按相同起点清理，删除审计独立保留 90 天。即使外部对象清理失败，已到期的数据库正文和普通日志仍会清除。完成后只保留删除回执、必要关联键和无正文审计，供防复活及清理验证；可确认全部清理的控制记录在 90 天窗口后移除。未完成的作业持续记录未完成状态和必要控制信息，不能把重试或保留控制解释为延长原有 30/90 天期限；超过期限仍未清除属于未达要求，须处理。

管理员 `GET /admin/cleanup-jobs` 查看持久告警；`POST /admin/cleanup-jobs/{job_id}/retry` 需管理员会话和 CSRF。界面“一键强制删除”仅经审计重新推进，不能跳过权限、评测关联、清理验证或安全等待。告警渠道为持久化记录与管理员后台，没有新增邮件/第三方通知服务。

所有者可在任务中按用途和 `video`/`summary` 范围授权，并查看或撤销同意。管理员默认仍仅看元数据；必须主动填写相同用途，通过 `/admin/tasks/{id}/result|export|video?purpose=...` 请求对应内容。摘要授权不授予视频权限。服务端在视频读取前后逐段重新核实当前会话、任务状态与同意；撤销后停止后续可中断传输。每次管理员访问有允许/拒绝审计，不记正文；系统不收回已被下载到外部的副本。

### 备份状态与人工准备

当前没有建立整盘/数据库快照的完整备份清单，也没有自动删除用户 SSD 或外接盘文件。本包能清理已登记的、任务专属的私有 S3 `BACKUP` 副本，并实际检查删除结果；未核验的整库、磁盘或外部备份不能据此声称清除。

因此 `BACKUP_INVENTORY_CONFIRMED=false` 为默认，回执保持 PENDING；已登记副本失败立即告警，尚未核验状态达到删除后 30 天时也持久告警，不将其转成成功或延长期限。只有部署者逐项核实所有备份位置、任务覆盖和清理方法，并确认没有未登记副本后，才可将该配置设为 true。该配置是部署者的清单确认，不是程序自动发现备份的证据。

**现行CR-001边界：** CR-D09/10已取消新增内容备份及常规内容恢复交付，S3-12须核实既有SSD/外接盘、自动快照及基础设施副本，先清点、隔离、核实并提交专项清理审批；仍履行原删除后最迟30天义务，超期/未知记录未达标。实际退役前保留受控清理，不将未知状态改成成功，也不按本指南直接删除历史文件。

### 手动恢复的安全顺序

新S3-12不再主动创建内容备份或以新增内容快照进行常规恢复演练。以下是历史工具对任何另行获准恢复仍必须保持的防复活顺序，不构成恢复/删除数据授权。任何手动恢复必须先停止 API/Worker，在私有环境恢复快照，保留**当前**独立删除记录卷，先迁移，再执行删除重放，最后恢复访问。示例中的时间必须换成真实快照创建时间，不能填当前时间代替：

```powershell
# 在 deploy/，先停止应用，数据库和对象存储保持私有。
docker compose --env-file .env.example stop api worker
# 部署者在此离线恢复经过核验的数据库/对象快照；不要回滚 deletion-control 卷。
docker compose --env-file .env.example run --rm --no-deps api python -m app.migrate
docker compose --env-file .env.example run --rm --no-deps api python -m app.deletion_control restore --snapshot-created-at "2026-10-30T08:00:00+00:00"
# 检查重放/清理状态后，再开放 API；不要因命令退出就假定物理清理已经完成。
docker compose --env-file .env.example up -d worker
docker compose --env-file .env.example up -d api
```

恢复入口重新设置删除栅栏并重开资产清理，即使快照中的资产已标为 DELETED，也不视作现在的删除证据。恢复同时撤销旧会话和旧内容同意，用户须重新登录、重新授予任务访问。普通启动也会在接受请求/领取任务前重放未应用的删除意图；缺失、损坏或部署身份不匹配的独立记录会阻止启动/就绪，不能通过新建空卷绕过。可用 `python -m app.deletion_control check` 核对；这不是备份清理完成证明。

独立记录只含任务/用户标识及删除时间，不含正文、文件名或凭据，按 90 天窗口清理。当前离线恢复入口拒绝未来时间或 90 天及更早的快照，因为已保留记录不足以证明其安全；这是当前恢复工具的限制，不是对用户数据/备份期限的修改。此类恢复须另行提出保全证据和安全方案，不能绕过检查。

验证使用隔离 PostgreSQL、临时时钟/目录、合成媒体和模型替身。完整回归 230 项通过；最终受影响删除/恢复/授权测试 35 项通过，包含长租约的 1800/1801 秒边界。前端构建及本地模拟接口的 Chrome 交互检查通过。实际 HTTP 验收确认原片、四类评测对象和双语 SQL 正文被后台清除，未核验备份仍为 PENDING；没有执行真实用户视频外发、模型调用或用户磁盘备份恢复。
