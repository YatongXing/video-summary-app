# 验收标准（AC）— Video Summary App

AC-01～22 定义产品验收，AC-23～26 定义本机部署验收。具体场景及执行方式见[端到端测试计划](E2E_TEST_PLAN.md)。

| ID | 验收标准 |
| --- | --- |
| AC-01 身份与角色 | 普通用户可用邮箱/密码注册，账户持久保存且能用已注册信息再次登录；每次新登录或会话失效后重新登录均需密码，不提供免密码自动登录；MVP 无邮箱验证/审核步骤。注册账户默认普通角色，注册参数不能提升权限。管理员仅由部署者手动创建，不开放管理员注册；密码安全哈希存储，不明文保存。注册/登录限速可配置且不得仅依赖 IP。 |
| AC-02 身份、授权与私有任务 | 未登录用户不能用核心功能；上传者须确认具有处理授权才可提交；USER 和 ADMIN 均不能通过个人入口读取或操作他人任务、视频和结果。 |
| AC-03 媒体验证 | 本地与 URL 导入均接受 MP4/MOV，最大 2 GB、最长 2 小时；视频编码 H.264/AVC；如含音轨，编码为 AAC/MP3。无音轨视频可走视觉理解并披露无可用语音。服务端验证实际大小、容器、编码、时长、可解码性；不只依赖扩展名/MIME/URL 后缀。超限/不支持/损坏等输入失败给出可理解说明，终止任务，不静默截断。允许容器/编码组合须经技术验证且不得擅自扩展白名单。 |
| AC-04 扣额时点与自然恢复 | 普通用户初始且最多 1 次，管理员不限。上传/校验/排队不扣，实际开始处理时扣 1 次。余额为 0 时每 6 小时恢复 1 次，达到 1 时停止；再次降为 0 时重启。旧余额 2 或 3 按 1 计，零余额沿用已有计时。退款使余额回到 1 时恢复停止。服务端为准，倒计时不依赖登录或时区；退款不重置自然恢复计时。 |
| AC-05 退款规则 | 内部错误（含 Worker 崩溃导致失败）、外部模型服务超时/限流/不可用退款；未知原因默认退款并记录；明确用户输入问题或主动取消不退已扣额度。每个符合条件的失败事件最多退款一次；同一退款事件重复处理幂等，且只能返还已扣机会；同任务未再次扣额的重试失败不得重复创造机会，模型超时后第 4 次及之后重试也不另扣处理机会。普通用户余额不超过 1。开始前失败无需退款。取消/错误竞态按服务端最终状态及可审计原因判定，无法确定则按未知错误退款。 |
| AC-06 失败可见性 | 预处理失败终止并向用户说明原因；不暴露内部堆栈、凭据、密钥或敏感服务器细节。失败分类、退款结果和重试资格可解释；额度提示为「同一任务重试不额外扣机会」。 |
| AC-07 重试计数 | 首次处理不计重试；滚动 5 分钟内前 4 次重试可接受，第 5 次已接受重试触发冷却；每任务累计最多 20 次已接受重试，第 21 次拒绝。手动/自动重试统一计数；重复投递同一请求不得重复计数。冷却/上限拒绝不计数、不开始处理。 |
| AC-08 冷却阶梯 | 任务的第 1/2/3/4 及后续冷却依次 1/5/15/30 分钟，30 分钟封顶；冷却级别在同任务中不重置，仅前一冷却结束后触发新冷却时推进；新任务从第一级开始。冷却请求不开始处理、不计重试、不延长冷却；冷却结束后仍检查滚动窗口。 |
| AC-09 取消与终态 | 排队取消转为 `CANCELLED` 且不开始处理；处理中取消尽快终止并禁止后续自动重试/重新生成，已扣额度不退。取消为终态，重做须新任务。成功已发生时保留 `SUCCEEDED`，不得被迟到取消覆盖；重复取消无额外副作用。 |
| AC-10 队列与并发 | 校验通过后按提交时间 FIFO；时间相同按用户 ID、任务 ID 排序。更早任务仅因所属普通用户已有活动任务、未扣过机会且额度不足，或两者同时成立而受阻时，可启动其他用户最早可运行任务。其他阻塞停止扫描。同用户任务保序，恢复资格后依原排序领取，并记录阻塞、越过及实际启动顺序。普通用户同时最多 1 个处理中任务，但可提交多个。总并发可配置；管理员无限额度但无默认优先级。 |
| AC-11 状态与时间 | 界面只使用 Queued、Processing、Completed、Failed、Cancelled 五个状态；`SUCCEEDED` 对应 `Completed`。不增加用户可见阶段或承诺精确 ETA。处理进度可见；成功仅更新页面、不弹窗。所有时间 UTC 保存、按需本地显示。任务日志含提交/开始/完成时间、排队/处理时长、最终状态、失败原因和重试记录。 |
| AC-12 处理性能 | 60 分钟视频成功任务实际处理时长 P90 ≤20 分钟，从实际开始至成功结束，不含排队；失败另报且不进入成功样本。报告记录环境、并发/负载和样本量。不得描述为已实现/验证；不设固定可用率或任务成功率门槛。 |
| AC-13 多模态与语言 | 处理流程包括校验、必要预处理、画面/音频分析、时间对齐融合、摘要/关键事件时间戳、输出验证和结果展示。支持中文/英文语音及摘要；其他语言不在 MVP。页面仅展示详细摘要和按时间排序的章节，保留语言切换、播放和章节跳播。摘要说明影响理解的音画局限。 |
| AC-B1 处理模型（阶段 B） | 默认模型为 Qwen3.8-Omni-Flash。正式实例同时提供 DeepSeek-V4.1-Flash，无 effort。部署配置停用 DeepSeek 时只提供 Qwen。缺省及旧任务为 Qwen，上传或导入提交时固定，重试不变；非法或停用值在开始处理前拒绝。 |
| AC-B2 DeepSeek 处理与清理（阶段 B） | 句级转写与有界关键帧对齐原视频。两种语言各发布详细摘要及有证据的章节，保持播放、跳播和 Markdown。无音轨、近数字静音及明确无词可发布带无语音说明的纯画面结果，章节与内部关键事件由有效帧号映射到源 PTS。ASR 服务故障不发布。思考模式、三档预算和结构校验见[模型流程](ARCHITECTURE.md#4-输入模型与输出流程)。明确截断单独归类，保留合法用量。DeepSeek 摘要默认最多等待 3600 秒。DeepSeek 摘要统一使用 SSE，收齐结束事件并通过原有双语校验后发布。断流不发布部分结果。取消、超时、租约失效或维护关闭后不得发布迟到结果，未知提交不重发。验证应用工作区及历史自有 OSS 音轨清理。新临时音轨由供应商处理到期，应用不标为已物理删除。 |
| AC-14 Markdown 下载 | “我的任务”的成功结果提供“下载 Markdown”，按当前语言下载 `video-summary-zh.md` 或 `video-summary-en.md`。文件只含对应语言的摘要标题及正文、章节标题及有序的时间列表，时间为普通文本 `HH:MM:SS`。旧任务可直接下载。 |
| AC-15 内部结果成功门槛 | 后端在开放下载前验证必需字段、类型、语言值及章节时间顺序。既有修复路径仍无效时任务失败，按系统错误退款且禁止下载。DeepSeek 明确截断或无效响应直接失败，单次尝试内禁止额外模型调用。只有摘要及 JSON 满足最低输出要求才是 `SUCCEEDED`。 |
| AC-16 管理员元数据 | 管理工作台只返回白名单元数据，自己的任务也没有内容操作。Task ID 可精确或按字面部分匹配，非空提交、清空复位；分页、稳定排序、限速及超时按[接口规范](ARCHITECTURE.md#内容权限与管理接口)验证。 |
| AC-17 所有者内容与退役入口 | USER 和 ADMIN 经个人入口查看本人摘要、双语 Markdown、视频和 Range。跨用户、无会话、角色变化及已删内容按契约拒绝；旧排障请求和旧目的授权 API 无旁路。个人任务名称下只显示一次 Task ID 和复制，导入成功提示不显示；反馈入口仅在配置合法邮箱时显示。 |
| AC-18 保留与到期 | 自任务创建起 30 天保留所有状态的任务数据和普通任务日志；到期仍处理的任务须安全停止/终止后再清理。 |
| AC-19 主动删除 | 所有者删除立即移出列表并禁止访问、同步关闭并清退历史授权记录；停止或隔离 Worker，幂等清理受控内容及关联评测资料，隔离其他任务。移除删除记录/人工清理/备份核验产品入口；临时故障退避且限频重试，持续故障有部署者可发现信号，危险删除停止，受控诊断/再推进有审计；参数/命令先审核。只有实际验证完成才标成功。 |
| AC-20 备份与审计 | 不主动创建应用内容备份，部署避免新增含内容的整库备份/系统快照；历史副本先清点隔离核实再批准清理，保留必要清理和获准恢复防复活，过渡期不放宽原清除期限。删除审计各事件起 90 天且到期清理；未完成作业留必要控制，不算完成。明确应用资产清理边界及无法恢复/介质历史字节/下载/供应商副本限制。 |
| AC-21 URL 边界 | MVP 提供 URL 导入。首轮仅接受经服务端安全校验、合法可直达的 HTTPS 视频文件 URL；阻止本机/内网访问、危险重定向、超限下载及凭据泄露，拒绝平台播放页面。不得绕过 DRM、访问限制或技术保护；YouTube/Bilibili 播放页面集成须另行评估授权路径。 |
| AC-22 质量评测 | 基线集为 15 个授权视频、项目负责人本地下载并通过本地应用界面手动评测、每视频一名标注者且无第二人独立复核；报告披露此限制、指标分母、缺失/不可评估项。对成功匹配事件报告时间戳误差中位数、P90，以及误差在 ±5 秒内（含边界）的匹配事件比例；±5 秒仅为初始评测容差，不是系统整体质量合格门槛。正式质量阈值须待基线后确定。 |

## 本机部署验收

| ID | 验收条件 |
| --- | --- |
| AC-23 资源与迁移 | 新实例只绑定 IPv4 回环地址，依赖在私网，应用以非 root 运行。新空库完整应用 001～012，逐字节核对 SQL 和迁移登记。重复初始化或未知身份受拒。 |
| AC-24 身份与门禁 | 初始化、维护 owner 和 runtime 凭据隔离，runtime 的 DDL、SET ROLE 与开门尝试受拒。初始 CLOSED，重启保持，控制失信时拒业务；可信 OPEN 后恢复处理。 |
| AC-25 在途安全与故障发现 | 关闭门禁后续流和 Worker 在检查点停止后续业务，未完成工作可诊断，已登记资产可清退。分辨计划维护与依赖故障；巡检启用时验证首次、持续及恢复事件。 |
| AC-26 运维与恢复 | 核对实际镜像和保留的卷、控制身份与部署配置。失败先隔离，恢复须重放删除并清退旧会话。合成验证环境按项目归属回收。 |

执行方法见[端到端测试计划](E2E_TEST_PLAN.md)和[本机运维](../deploy/README.md)。
