## 1. 总体顺序和共同门槛

既定六阶段：分析（已完成）→文档/设计审批（WP00已接受、当前WP01设计）→分包实现→新回归/人工验收→单独启动S3-11→单独启动新范围S3-12。不因文档批准自动推进后续阶段。

所有包开始前均需：
1. 产品负责人明确授权该包的范围、可写路径及允许的测试/数据环境；本轮不包含这些权限。
2. 前置包退出门槛有可复核证据，当前PRD/AC/ADR-005与具体契约版本一致。
3. 当前implementation未提交工作得到保留；按第5节确定版本/指纹，禁止reset/clean或覆盖既有文件。
4. 涉及数据操作先明确对象、隔离边界、失败处理和升级回退；不得默认制作含用户内容的备份。
5. 非模型测试使用隔离_test数据库、唯一schema/bucket/临时目录、合成媒体及模型替身；不用真实Key。
6. 身份/授权、迁移、删除、恢复和并发按原项目规则接受独立测试/审查；派发只在相应包获准后进行。

关键路径：
`CR-WP00 → CR-WP01审核通过 → CR-WP02 → CR-WP03 → CR-WP04 → CR-WP05 → CR-WP06 → CR-WP07 → 单独S3-11 → 单独S3-12`

WP04中与授权无关的删除设计可在契约冻结后准备，WP05可在接口稳定后准备；涉及共享鉴权/迁移/删除的集成与发布保持上述退出依赖，不据此自行并行启动。

### S3-12开始前及退出条件

- 诊断日志目录/脱敏、清理积压/持续故障可发现、部署者受控审计式再推进验证。
- 历史介质/对象/自动快照清点、隔离、核实；提交具体目标、归属、影响和方法，清理专项获批后才执行。
