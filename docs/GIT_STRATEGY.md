# Git 分支策略

**状态：** 当前采用。Step 3 本地 `implementation` 分支从已同步的最新 `main` 建立；远端同名分支仍在较早祖先提交，后续只以快进方式更新。

| 分支 | 用途 | 创建基点 | 合并目标 |
| --- | --- | --- | --- |
| `main` | 审阅后的稳定需求基线与后续已批准变更 | 初始提交 | — |
| `architecture` | 架构、安全、数据流设计文档 | `main` 的需求基线提交 | `main` |
| `implementation` | 经批准架构后的产品实现 | 已合并架构的 `main` | `main` |
| `testing` | 经批准实现后的测试资产、自动化和验证记录 | 实现基线 | `main` |

每个分支只承载所属阶段的变更，合并前审阅需求/验收标准对齐。Step 3 的计划及后续实现先保留在本地 `implementation`；提交和推送遵守用户逐次授权，不覆盖远端历史。
