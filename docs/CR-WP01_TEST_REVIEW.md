## 3. 可重复并发交错B1～B10

| ID | 显式交错 | 判定 |
| --- | --- | --- |
| B1 两次再生 | R0；A持source锁暂停，B用expectedR0等待；A提交R1后放B | B409，仅R1有效，R0所有入口拒绝。 |
| B2 同幂等 | A写请求/回执后COMMIT前停；B同key/body等待；分别令A提交/回滚 | 同一R1或仅B建一R；同key异体409，无多建/续期。 |
| B3 删旧请求 | R0→R1后用旧R0删除；反向先删R0再尝试expectedR0 | R1不受影响；反向409/显式新CREATE，不复活R0。 |
| B4 删task vs生成 | A写删除intent后停，B生成等待；分别SQL提交/失败；反向先生成 | intent均禁止新授权；或后续删除同事务终止R1。 |
| B5 跨期锁 | 请求tE前发，source锁tE后释放；同时测试now固定旧值 | 锁后真实时间拒绝，创建从记录时间非响应时间起算。 |
| B6 流中失效 | Fake read返回、第二次检查前barrier；另一连接提交失效 | 当前尚未yield块不得输出；已经过最后检查发出的在途字节不承诺追回。 |
| B7 旧cleaner I/O | token1+EX在I/O暂停至claim过期，B尝试接管 | B不能先拿token2/删除，EX未释放不得接管；旧token不记完成，释放后重验定位/结果。 |
| B8 父死子活 | 父SH/pass_fds启动阻塞写子进程；kill父但子仍活 | EX仍失败，子退出后才清理；unlink/rebuild inode、误LOCK_UN或FD关闭反例必须探测。 |
| B9 故障失明 | 卡住扫描线程/单对象I/O，主循环仍运行；另测日志输出失败/DB不可用 | 独立health/poll按阈值发现进度陈旧；持久信号存在，未知不能healthy。 |
| B10 切换/恢复 | 每个schema/role/终止/epoch/开放点kill；旧连接未断的负例；恢复含旧码/会话 | 始终维护封闭；旧binary/旧凭证失权；恢复终止新旧授权并换真key/epoch才开放。 |

以Event/Barrier控制、第三autocommit观察者核对；超时只防挂死，不能算通过。B7按最终互斥次序收紧：拿不到EX不先领取token2，不能把“已拿新token”作为正常流程。

额外补充：生产DB→SH与清理EX→DB的死锁负例必须被协议拒绝；crypto生成SH key与退役UPDATE的双连接交错，退役不能漏掉未提交生成；运维回执/审计COMMIT失败不得发生调度/I/O。
