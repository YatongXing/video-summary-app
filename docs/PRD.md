# Video Summary App — 产品需求文档（PRD）

产品规则按已验收的 [CR-002](CR-002.md) 与 CR-001 继续有效的删除、运行规则整合。接口细节以 CR-002 为准。实现和正式部署状态见[实施计划](IMPLEMENTATION_PLAN.md#当前交付状态)。

## 1. 产品概述与 MVP

面向中国个人用户的视频理解与总结网站。用户上传本地视频或提交视频 URL，系统导入、校验并预处理输入，分别分析画面和音频，按时间对齐与融合信息，生成带时间戳的视频摘要，检查输出并向用户展示。结果可导出为中文或英文 JSON。

MVP 支持本地文件和视频 URL 导入；单个视频最长 2 小时、最大 2 GB。用户须确认拥有上传、导入及处理授权。首轮 URL 范围**已确认**为经安全校验、可直接合法获取媒体文件的 HTTPS 地址；YouTube、Bilibili 等平台播放页面或需登录、绕过访问限制/DRM/平台技术保护才能取得的地址不在该范围，未来平台集成须另行评估合法授权路径。不得静默截断超限视频。

## 2. 已确认的身份、权限与隐私要求

- 普通用户通过邮箱和密码注册、登录；核心功能必须登录，不提供匿名试用。
- 每次新登录都要求用户重新输入密码；MVP 不提供免密码自动登录。会话失效后重新登录同样要求密码，具体会话期限由实施配置确定。
- MVP 注册账户须持久保存，用户可用已注册邮箱和密码再次登录。首轮不要求邮箱验证或审核；注册/登录界面保留未来扩展空间，密码找回等流程留待后续决定。身份模块应可扩展，不以界面展示代替实际登录和服务端鉴权。
- 注册创建的账户默认只能是普通用户。客户端传入角色或权限字段不能提升权限；管理员账户仅由部署者手动创建，不开放公开管理员注册。
- 密码不得明文存储，必须以安全密码哈希形式保存。具体算法、参数和密钥管理属于后续设计事项。
- USER 和 ADMIN 通过个人任务入口读取自己的视频、摘要及双语 JSON。两种角色均拒绝跨用户内容访问。服务端按当前会话、数据库角色、任务归属、任务状态和删除控制校验，持续检查可中断的媒体读取。
- 管理员工作台独立显示白名单任务元数据，包含状态、时间、错误、重试和额度统计。包括管理员自己的任务在内，元数据页均不提供内容入口。按 Task ID 搜索与分页，范围、匹配规则和限速以 [CR-002](CR-002.md#权限及接口) 为准。
- 任务名称下显示真实 Task ID 及复制操作。展开结果和导入校验通过提示不重复显示。非空搜索由提交触发，清空输入立即恢复默认列表。
- 排障请求、范围授权、24 小时、重新生成和待处理队列属于历史规则，原接口退役。旧请求和任务编号不能授予内容权限。
- 注册与登录有基本限速。错误、日志及审计只保留必要的脱敏信息。反馈邮箱由公共配置提供，合法且已配置时显示邮件链接。

## 3. 媒体输入与校验

两种输入方式使用相同媒体白名单：MP4、MOV 容器；单视频不超过 2 GB、时长不超过 2 小时。初始视频编码白名单为 H.264/AVC；如视频含音轨，音频编码白名单为 AAC、MP3。无音轨视频可以进行视觉理解，并说明无可用语音。容器/编码组合和预处理兼容性须进行技术验证，验证不得擅自扩大白名单。

服务端必须检查实际文件大小、容器、编码、时长和可解码性，不能只信扩展名、浏览器 MIME 或 URL 后缀。首轮 URL 输入仅接受经安全校验的 HTTPS 直达媒体地址；须防止访问本机/内网资源、危险重定向及超限下载，不把 URL 中凭据或查询参数写入日志和导出。上传/导入未完成或在额度扣除前校验失败，不扣也不需要返还机会。预处理失败时终止任务并说明用户可理解的原因；明确的用户输入问题（含不支持媒体、确认损坏文件）不返还已扣机会。不得向用户暴露堆栈、密钥、凭据或敏感服务器信息。

## 4. 账户、额度、退款与重试

### 额度和自然恢复

- 普通用户初始 3 次处理机会；管理员不限处理机会。
- 实际处理开始时扣 1 次；上传或排队不扣。同一任务重试不额外扣机会。
- 当普通用户余额低于 3 时启动自然恢复，每 6 小时恢复 1 次，直到余额为 3。后续使用不重置已启动的计时；余额达到 3 时计时停止，之后再次低于 3 时重新开始计时。
- 界面显示当前余额和距离下次恢复的倒计时，不承诺精确恢复时间戳。服务端为权威来源；离线、登出或时区变化不改变实际恢复结果。
- 系统错误退款独立于自然恢复，不重置自然恢复计时。退款使余额到 3 时自然恢复停止，余额以后降低时重新开始。
- 每个符合条件的失败事件最多退款一次；同一退款事件重复处理必须幂等，且退款只能返还已扣机会。同任务重试若未再次扣额，不得凭重试失败重复创造机会。普通用户余额不超过 3。

### 失败分类与退款

| 类别 | 配额处理 |
| --- | --- |
| 明确的用户输入问题 | 已扣机会不退款；扣除前校验失败则没有扣费。 |
| 内部系统错误 | 退款。 |
| 外部模型服务超时、限流或不可用 | 退款。 |
| 无法确定原因的未知错误 | 默认退款并记录错误。 |
| 用户主动取消 | 已扣机会不退款；尚未开始处理则无须退款。 |

取消与系统错误竞态按服务端最终任务状态和可审计失败原因分类；若无法确定责任，按未知错误退款。任务开始前未扣机会时，不创建退款。

Worker 意外退出或服务器重启造成的任务失败按内部系统错误退款；恢复执行同一任务不得再次扣额。模型 API 超时按外部服务超时退款，自动重试仍属于同一任务，不因第 4 次或后续重试额外扣处理机会；从第 4 次模型超时重试起，在用户界面提示反复失败及可能的 API 费用，重试继续遵守下述滚动窗口、冷却和累计上限。处理机会与外部模型实际 Token 费用分别记账，不能把 API 成本直接解释为用户处理机会。

### 重试窗口与累计上限

- 首次处理不算重试。按滚动 5 分钟窗口统计已接受的重试；窗口内前 4 次可接受，第 5 次已接受重试触发冷却。
- 每个任务最多接受累计 20 次重试；第 21 次拒绝。用户手动和系统自动重试均计数，重复投递同一重试请求不得重复计数。
- 因冷却或累计上限而拒绝的请求不是已接受重试，不开始处理。冷却中的请求不延长当前冷却。
- 冷却结束后仍按适用的已接受重试记录重新检查滚动窗口。累计次数、窗口规则、冷却同时生效。
- 同一任务被取消后为终态，不可重试；用户要处理同一视频须新建任务，新任务不继承旧计数。

### 冷却阶梯

首次、第二次、第三次、第四次及之后触发的冷却分别为 1、5、15、30 分钟；30 分钟封顶。服务端在触发时启动计时并禁止该任务开始新的处理尝试。任务内冷却级别不重置。冷却到期后，只有再次触发新冷却才推进级别。新任务从第一级开始。自动与手动重试遵循相同限制；自动重试不能绕过冷却。

## 5. 队列、时间、状态与用户反馈

- 任务输入校验通过后进入队列，按校验成功后的提交时间 FIFO。时间戳相同则按用户 ID、任务 ID 排序。唯一允许的越过情形：队首任务仅因所属普通用户已有活动任务而暂时不能启动时，其他用户最早的可运行任务可先启动；同一用户任务仍依原顺序，管理员不因此获得优先级。调度日志须能解释原始顺序、阻塞原因和实际启动顺序；防长期饥饿的具体机制待实现验证。
- 普通用户最多同时处理 1 个视频，但可提交多个任务。系统总并发上限可配置。管理员任务遵循同一 FIFO，不默认插队。
- 时间戳统一以 UTC 保存，界面按用户本地时区显示。任务至少记录提交时间、处理开始时间、完成时间、排队时长、处理时长、最终状态、失败原因和重试记录。
- 用户界面只使用五个状态：Queued、Processing、Completed、Failed、Cancelled。内部成功状态 `SUCCEEDED` 对应界面 `Completed`；不得向用户增加更多处理阶段。冷却/重试等待不增加新的用户可见状态。
- 取消排队任务后转为 `CANCELLED` 且不开始处理。取消正在处理的任务时请求尽快停止，阻止自动重试和结果再生成。已扣额度不退。取消为终态；重做须新建任务。
- 若取消请求处理时任务已经成功，保留 `SUCCEEDED`，不改为 `CANCELLED`。并发的取消请求不得造成重复扣退或副作用。
- 界面显示权威状态及处理进度，不承诺精确完成时间或 ETA。成功时仅更新界面、不弹成功对话框；失败时说明原因和是否可重试。

## 6. 双语摘要与 JSON 导出

MVP 接受中文、英文语音，摘要输出支持中文或英文，其他输入语言不在范围内。中文和英文 JSON 使用同一结构，并须可解析、语义完整。输出语言字段为 `zh` 或 `en`。

结果页面保留已有呈现要求：一句话总览、3–7 条要点、按时间排序的章节、通常 3–10 个关键时刻、可跳转时间戳和音频/视觉局限说明；内容不足时可减少关键时刻并说明原因。JSON 1.0 导出只遵循下述字段契约，不增加未定义的 JSON 字段。

初始 JSON 结构如下，字段集合和禁用字段见下文要求：

```json
{
  "schema_version": "1.0",
  "video": {
    "filename": "example.mp4",
    "duration_seconds": 3600
  },
  "language": "zh",
  "summary": "Video summary text",
  "key_events": [
    {
      "timestamp_seconds": 125.5,
      "title": "Key event title",
      "description": "Key event description"
    }
  ]
}
```

- `schema_version` 是表示 JSON 数据契约版本的字符串 `"1.0"`，不是应用或模型版本。
- `video.filename` 对本地输入为原始上传文件名；URL 输入为导入后安全确定的展示文件名，不含 URL 查询参数、凭据或本地完整路径；`duration_seconds` 为视频时长秒数。
- `language` 只能是 `zh` 或 `en`；`summary` 为摘要文本。
- `key_events` 按视频时间排序；事件包含数字型 `timestamp_seconds`（允许小数）、`title` 和 `description`。
- 不导出 `importance`、逐字稿/完整转录、用户 ID/邮箱、服务器文件系统路径/存储地址、任务 ID 或视频 ID。
- 没有可识别关键事件时允许 `key_events: []`，前提是摘要满足最低输出要求。
- 后端在提供下载前须校验 Schema、必填字段、类型、语言值和事件时间顺序。系统可有限次数自动修复或重新生成，具体次数是可配置内部参数，暂不在 Step 1 固定。
- 修复后仍无效时不得提供无效 JSON 下载；任务记为失败，并按系统错误规则返还配额。只有摘要和规定 JSON 均满足最低要求，任务才可标为 `SUCCEEDED`（界面显示 `Completed`）。

## 7. 数据保留、删除与恢复

- 任务、内容资产和普通任务日志从任务创建起保留 30 天，覆盖全部五状态及未完成任务；到期仍运行时安全停止或隔离后清理，历史授权仅作关闭兼容。
- 普通用户或管理员删除自己拥有的任务时，接受请求后立即移出用户列表并拒绝新内容读取，取消排队、停止或安全隔离活动处理，禁止后台重试/迟到结果重建；同步处理历史授权关闭与清退。
- 清理覆盖应用控制的原片、音频、帧、截图、片段、临时媒体、缓存、中英文摘要、章节/事件/时间戳正文、SQL/JSON 导出、内容型记录及关联评测副本、标注、模型输出和失败案例。去标识化不豁免关联删除，不影响其他用户/任务。
- 保留认证/归属、幂等、Worker 并发与代次栅栏、防迟到发布、受控重试、状态一致性、脱敏诊断、存储隔离和实际完成验证。
- 移除普通用户/管理员“删除记录”入口和查询操作，移除管理员“清理告警与人工处理”、一键人工清理和备份核验产品界面；保留任务正常删除按钮/确认及后台保障。
- 临时清理故障带退避和频率上限重试；持续故障产生部署者可发现的错误及故障信号；危险或归属不明操作停止自动删除。提供受控、可审计的部署者诊断和再推进方式，清理采用 PENDING、RETRY_WAIT、BLOCKED、COMPLETED 四态、单 job_version、全局清理互斥及 status/health/retry。WP04 验证与 WP07-A 开放前故障发现要求见[删除设计](CR-WP01_DELETION_OPERATIONS.md)和[执行清单](CR-WP07A_FORMAL_RUNBOOK.md)。
- 接受删除只表示访问已禁止、后台清理已提交。只有应用控制的数据库正文、私有对象、派生文件、工作目录和相关资产实际清理并验证完成，内部才标记成功；失败或未知不得虚报成功，不要求另建删除历史页面。
- 删除审计按各审计事件发生时间保留 90 天，到期清除；只含必要内部标识、操作类型、请求/完成及事件时间、结果和脱敏错误分类，不含内容、可恢复副本或有效访问凭证。未完成作业只保留必要执行控制到完成或经授权解决，不因此视为完成。
- 不主动创建用户原片、派生媒体或摘要的应用级备份；后续部署避免新的含此类内容的整库备份或系统快照。可保留无用户内容的代码、配置模板、数据库结构和部署说明用于软件重建。
- 历史备份、自动快照及基础设施副本先清点、隔离、核实，再经批准清理；处置前保留必要受控清理。历史副本仍遵守原删除后最迟 30 天清除义务；超期/未知须报告，不能擅自删除、延期或报成功。任何获准恢复先持久维护门禁并隔离，重放独立删除控制、终止恢复库旧会话和新旧授权；账户状态不明不开放，不复活已删内容。WP07-A 分离初始化、维护和普通运行三种数据库身份及其凭据。不建不必要授权epoch/协议表，不承诺任意整机旧快照自动检测。
- 应用删除不承诺基础设施历史字节或物理介质安全擦除；不能收回用户/管理员下载副本，不能保证立即清除供应商控制的模型副本。S3-12 明确原片/摘要、数据库及关联账户/元数据丢失可能无法恢复的范围；重传/重算可能收费且结果不完全一致。

## 8. 性能与运行指标（目标未实现/验证）

60 分钟视频成功任务的实际处理时长 P90 不超过 20 分钟；从实际开始处理计至成功结束，不含排队时间。失败任务单独报告，不进入成功任务样本。测量需记录运行环境、并发/负载条件和样本量。此为需求目标，不代表已达成。

MVP 不承诺固定可用性百分比或任务成功率门槛。需记录成功、失败、取消、失败原因并监控成功/失败率与处理时长，区分内部故障和外部依赖故障。正式 SLO 可在收集运行基线后再考虑。

## 9. 质量基线

使用 15 个经授权、由项目负责人本地下载的视频，通过本地应用界面手动运行并记录初始质量基线。建议每类约 3 个：课程/讲座/演示文稿、编程教程/软件操作、会议/访谈/讨论、视觉主导且少语音、音视频歧义或潜在冲突；这是建议分布。素材不能满足时如实记录覆盖和限制。

每个视频由一名标注者标注关键事件、重要性、参考时间戳；不做第二人独立标注或独立裁定，报告须披露限制。初始评测中匹配事件时间戳误差在 ±5 秒内视为容差内，并报告匹配事件误差中位数、P90 和容差内事件比例；该容差不是系统整体质量合格门槛。保留模型输出、人工标注、评测结果和失败案例，用于比较模型/提示词版本。15 个样本只支持初步基线，不足以证明普遍泛化。先跑基线，再决定正式质量阈值，详见 [QUALITY_EVALUATION.md](QUALITY_EVALUATION.md)。
