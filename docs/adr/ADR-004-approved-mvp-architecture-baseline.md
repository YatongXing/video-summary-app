# ADR-004：MVP 架构基线及实施默认

**状态：Approved。批准人：产品负责人。批准日期：2026-10-29。** 本记录批准架构方向和下列具体设计默认；不表示模型能力、性能、费用或本机容量已经实测。ADR-001～003 继续有效，产品行为以 [PRD](../PRD.md) 为准。

## 决策

采用[架构文档](../ARCHITECTURE.md)中的方案 B 作为 MVP 最终设计基线：模块化应用、持久队列和独立 Worker；一个代码库，API 与 Worker 分别运行。前端为 TypeScript + React + Vite，首轮静态资源与 API 同源。首轮使用 Python API/Worker、PostgreSQL 作为业务及队列权威、本地 S3 兼容私有对象存储；先不引入独立 Broker。Windows 11 本地运行首选 Docker Desktop/Compose，安装和兼容性仍需确认。模型指定 Qwen3.8-Omni-Flash，通过服务端最小适配接口接入，不把 SDK 数据形状散入业务模块。

| 批准的实施默认 | 保留的验证边界 |
| --- | --- |
| PostgreSQL 单一调度临界区，按已确认排序键挑最早可运行任务；ADR-002 唯一条件允许越过。 | 并发、锁等待和长期饥饿仍需在规划负载下测量；若证据不足再比较 Broker。 |
| 租约代次阻止旧 Worker 写入；首轮配置 120 秒租约、30 秒心跳。 | 数值可配置，须经 Worker 失联、恢复及模型请求结果未知场景验证。 |
| 事务和唯一事件键保证扣额、退款、领取、重试、取消幂等。 | 故障注入和竞态测试须证明行为；不得改变 PRD 配额规则。 |
| 资产登记、删除栅栏、关联评测资料清理、失败告警和手动再推进；恢复时重放删除控制。 | ADR-003 与 30/90 天期限不变；必须证明不会复活已删资料。 |
| 服务端会话和逐请求授权；首轮认证限速按单账户 15 分钟 5 次失败暂停 15 分钟、同来源 15 分钟 20 次失败暂停 15 分钟，注册入口也按来源限速。 | 参数可配置；会话期限、管理员账户撤销和运营响应时间在实现评审时具体化。 |
| 本地文件和用户 URL 均先导入私有存储，再由适配器提供最少必要媒体。必要时只使用短时、只读、任务限定、可撤销的模型访问 URL。 | 不公开整个对象存储；公网入口具体方案、可撤销性和 2h/2GB 实际可行性仍需验证。 |
| MVP URL 首轮仅接受经安全校验的 HTTPS 直达媒体文件地址。 | 这是同日获批的产品范围收敛，已同步 PRD/SCOPE/AC；平台播放页面另作权利及技术评估。 |

## 依据与后果

产品负责人在 2026-10-29 明确接受当前架构基线、首轮 HTTPS 直达文件范围及此前提出的默认方式，并要求形成批准记录。此选择适合单人实验项目，减少独立服务和运维面；代价是 PostgreSQL 队列、本地存储、外部模型回连及删除一致性必须通过实际故障和容量验证。若关键证据失败，应提交最小替代方案和影响评估，不自动改动产品边界或已批准 ADR。

产品负责人已确认审阅并同意当前 Qwen 账号条款，条款审阅不再列作待批准决策；这不构成对服务实际区域、留存行为、性能或费用的测试结论。`.env` 中已配置密钥与地址，密钥仍不得入库；任何计费调用继续遵守 MVP 批次审批，真实视频外发还须先完成媒体访问路径和网络边界验证。
