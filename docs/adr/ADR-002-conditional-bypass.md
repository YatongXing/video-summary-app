# ADR-002：因单用户并发或额度受阻时有限越过队首

**状态：** Approved（产品负责人已批准）。

## 决策

任务通过输入校验后，按 UTC 提交时间、user ID、task ID 确定原始顺序。当更早任务仅因所属普通用户已有一个活动视频任务（USER_ACTIVE）、未扣过机会且无可用额度（NO_CREDITS），或这两个条件同时成立而受阻时，允许其他用户最早的可运行任务先启动。遇到账户停用、冷却或重试等待等其他阻塞仍停止扫描。每次领取从原顺序重新检查，较早任务恢复资格后优先领取。该例外不扩展为一般优先级调度。

同一普通用户的任务维持原顺序，不能启动第二个并行视频任务；全局并发配置仍生效。管理员无默认插队权。每次选择记录原排序键、阻塞原因、被越过任务、实际启动任务、开始时间和相关状态，足以解释启动顺序。并发领取、取消和重试交错不得破坏这些边界。

依据：[PRD §5](../PRD.md) 和 [AC-10](../AC.md) 的排序键、有限越过条件及并发上限；详细设计见[架构文档](../ARCHITECTURE.md)。

## 后果与待验证

普通用户额度上限从 3 降至 1 后更容易出现队首余额耗尽。允许跨账户有限越过，减少对其他账户的等待；原额度恢复、扣退和重试规则保持。防长期饥饿的具体阈值尚未批准；预计最多 5 人同时上传时先记录等待/越过数据，并在 10–30 人同时使用的模拟与故障测试中检查是否出现饥饿。未见证据前不自行填入数值或声称已解决饥饿。
