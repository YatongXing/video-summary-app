# ADR-002：因单用户并发受阻时有限越过队首

**状态：** Approved（产品负责人已批准）。

## 决策

任务通过输入校验后，按 UTC 提交时间、user ID、task ID 确定原始顺序。仅当队首任务因其**普通用户已有一个活动视频任务**而暂不能运行，且除此之外符合启动条件时，允许其他用户最早的可运行任务先启动。该例外不扩展为一般优先级调度。

同一普通用户的任务维持原顺序，不能启动第二个并行视频任务；全局并发配置仍生效。管理员无默认插队权。每次选择记录原排序键、阻塞原因、被越过任务、实际启动任务、开始时间和相关状态，足以解释启动顺序。并发领取、取消和重试交错不得破坏这些边界。

依据：[PRD §5](../PRD.md) 和 [AC-10](../AC.md) 的排序键、唯一越过条件及并发上限；详细设计见[架构文档](../ARCHITECTURE.md)。

## 后果与待验证

PRD/AC/E2E 已在本地同步唯一越过条件；本 ADR 保留决策理由。防长期饥饿的具体阈值尚未批准；预计最多 5 人同时上传时先记录等待/越过数据，并在 10–30 人同时使用的模拟与故障测试中检查是否出现饥饿。未见证据前不自行填入数值或声称已解决饥饿。
