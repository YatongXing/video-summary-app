## 现行效力（2026-11-07）

7. 默认Main/Coding/Testing；WP03/04/07按风险定向只读安全复核。逐包负责人验收，不自动推进。
8. 未被替代的30天内容保留、实际删除/隔离、防复活、事件90天审计、无新内容备份/历史先核实批准及不可恢复风险保持。

## 1. 背景和决策

S3-10 后人工验收要求替换目的授权、多条无期限同意及删除/人工清理界面。业务实现尚未切换；ADR-001～004 原文保持不变，保留批准历史。

1. 沿用 React、Python API/独立 Worker、PostgreSQL 权威状态及私有 S3 兼容存储，不因此引入 Broker 或额外服务。
2. 管理员按所有权直接访问自己任务；访问普通用户内容须当前有效的单任务授权。范围为摘要（含 zh/en 与 JSON）、视频或两者，按服务端检查。
3. 系统生成随机唯一任务码，同任务最多一有效码，从服务端成功创建起固定 24 小时，重新生成原子替换。身份、任务/用户关联、范围、到期、撤销/替换/删除及任务状态逐次检查。
4. 创建码同时产生普通用户请求；独立管理员有效队列直接显示码，按创建时间/请求 ID 升序。失效立即退出，新请求重新排队，无历史请求管理页面。删除请求同时撤销授权，不删除源任务。
5. 手动输入与列表入口共享服务端鉴权，解析不产生脱离原授权的长期权限。码不进公开 URL、普通日志或不必要持久浏览器存储，无效查询限速。
6. 正式切换统一终止旧目的授权，不自动转码；旧 API、升级/恢复/回退不得旁路新规则或复活旧授权。
7. 删除先禁止读取和撤销排障授权，再停止/隔离内容生产、逐项幂等清理并验证；保留归属、租约/代次、防迟到、隔离、重试和诊断能力。
8. 移除删除记录、人工清理及备份核验产品功能，替换为限频退避、持续故障信号、危险删除停止、受控且审计式部署者诊断/再推进；具体参数和命令先审核。
9. 删除审计按每个事件时间保留 90 天，无内容且到期清除；未完成作业留必要控制至完成或授权解决，不冒充成功。任务及普通日志自任务创建起 30 天继续有效。
10. 不主动创建内容备份，部署避免新含内容整库备份/快照，只保留无内容的软件重建资料。历史副本先清点、隔离、核实、再经批准清理；处置前保留必要能力和原清除义务。
11. 完成验收限应用实际控制的 SQL 正文、对象、派生文件/工作目录及内容资产；说明介质历史字节、下载和供应商副本限制，不承诺安全擦除。S3-12 明确不可恢复范围。

## 3. 待实施评审的技术方案

建议单一排障请求记录承载同次授权，数据库约束和事务配合实时到期校验；候选为高熵随机码、摘要查找及认证加密以供主体再次展示。具体表名/字段、算法/密钥、状态/索引、API、锁序/时间/幂等、限速、清理退避/故障发现/部署者命令由 CR-WP01 提交审核；它们不是已批准参数。

普通启动、当前删除仍依赖独立删除意图、部署身份校验和重放；取消备份不授权删除整个 deletion_control 模块/卷。历史 BACKUP 清理保留到实际处置完成，字段和能力退役需证据及授权。

## 4. 后果和验证

- 原片、摘要、数据库及关联账户元数据可能无副本可恢复；软件重部署不等于数据恢复。
- 再次展示访问码需要受控可恢复存储和密钥管理，仅哈希不能再次展示；持码不替代身份认证。
- 页面减少不减轻清理可靠性责任，持续故障必须确实可被部署者发现。
- 新验收覆盖并发、24小时、替换/撤销、请求删除、Worker竞争、失败及迁移，见 [CR-001_TEST_PLAN](../archive/cr/CR-001_TEST_PLAN.md)。
