# ADR-001：模块化应用、持久队列与独立 Worker

**状态：** Approved（产品负责人已批准）。

## 决策与依据

采用模块化应用、持久队列和独立的视频处理 Worker。账户/权限、任务/额度、上传校验、调度、媒体处理、模型适配、输出验证、删除及审计各有清晰职责；控制面与 Worker 分开运行。一个 Worker 可以处理一个完整任务，不预先拆分大量阶段服务或微服务。持久队列须支持失败恢复；具体实现仍须验证。

依据：[PRD §1、§4～8](../PRD.md) 的长视频处理、任务状态、额度、删除和 P90 目标；具体设计及待验证项见[架构文档](../ARCHITECTURE.md)。

## 后果与待验证

- 长任务不占用用户交互请求，但增加队列、租约、重复领取和跨进程状态一致性责任。
- 任务权威状态、扣额、退款、取消、重试与删除栅栏必须可审计、幂等且能从 Worker 崩溃中恢复。
- Python API/Worker、PostgreSQL 队列和本地 S3 兼容私有存储已作为 MVP 基线获批，见 [ADR-004](ADR-004-approved-mvp-architecture-baseline.md)；具体框架、对象存储产品和版本仍在实施时确定。
- 60 分钟成功任务 P90≤20 分钟是未验证需求目标。本 ADR 不声称该目标已达到。
