# CR-WP07-A 实施与隔离验证报告

完成日期：2026-11-07（Windows 本地时间）。目标为在 Docker Desktop 的 Linux 容器中全新部署。**本轮只实施并验证 G-01～G-03；没有创建、接管或开放正式实例。** 以下建议与清单供下一阶段审批。

## 实施结果

| 范围 | 已实现的行为 |
|---|---|
| G-01 持久维护门禁 | 新部署初始化为 CLOSED。门禁状态在独立 Linux 命名卷上，关联数据库和删除日志部署身份；缺失、损坏或身份不符拒绝业务。API、视频续流、Worker 领取和发布、事务提交及必要 I/O 都有检查。CLOSED 不阻存活诊断；已开始的 I/O 保留安全关句柄和清退定位。只有验证过的维护身份可以开关门，OPEN 前先提交删除意图重放。已发送字节和已经进入的单次系统调用不作撤回保证。 |
| G-02 数据库与维护身份 | 从全新空库、新桶和新控制卷初始化，原 001～011 全部执行。一次性基础设施身份、非超级用户维护 owner、非 owner 的普通运行身份各自独立，拒绝复用密码。API/Worker 只持运行数据库与私有桶必要凭据，UID 10001；历史请求表权限仅保留必要清退。DB/RustFS 不发布宿主端口，Web 仅绑定 IPv4 本机地址。 |
| G-03 实际故障巡检 | Windows 宿主巡检先核对实例和实际绑定，再探测 API、Worker、PostgreSQL、RustFS 和删除清理进度。记录故障、持续故障及恢复，有整轮时限。仅向本地测试文件写入无用户内容的事件。正式通知渠道、接收人和启动方式仍待批准。 |

沿用最新版 CR-002/WP06 权限：USER 和 ADMIN 可在“我的视频任务”查看自己的内容；跨用户拒绝，管理后台仅显示白名单元数据，退役排障接口不再开放。继续使用批准的前端构建产物，保留任务 ID 展示与复制、任意字符任务 ID 搜索及清空恢复默认。真实 Qwen 调用关闭，留 S3-11 单独授权。

## 独立验证

- 最终 Linux 离线回归 **322/322**；原迟到响应用例及门禁定向回归 **22/22**，Linux 锁、FFmpeg 后代和物理删除 **6/6**。旧 WP02 的阶段专用回归 **42/42** 用冻结的 001～010 副本另跑；正式候选配方的全新数据库则实测 001～011。
- 实际 Docker 和 Windows 巡检验证 **9/9**，覆盖 API、数据库、RustFS、Worker、持续故障和恢复，以及维护身份离线重放。另有真实权限、旧入口拒绝和目标对象删除后返回 404 的验证。未安装 Windows 正式计划任务，也未发送外部通知。
- 实际 Compose 最终镜像验收通过：初始及重启后仍 CLOSED、维护开门、非 root、仅 Web 本机发布；Chrome 验证两种角色的本人内容、双语结果、视频 Range/seek、管理页无内容和搜索。实际镜像 ID、源码比对和合成证据见独立报告。
- 故障测试停启指定隔离容器，未重启整台 Windows 或退出 Docker Desktop。视频流中途关门验证使用 HTTP 流和对象读取的受控检查点，未单独在长 TCP 视频连接上执行。

完整回归早期两次均在同一个 10 ms 假模型迟到响应测试失败。独立测试在同一环境验证了原因：新增音频读取检查重复刷新数据库租约，提前用完测试窗口。修复仅移除这部分重复刷新，保留可信门禁、本地取消、句柄关闭以及既有适配器、Worker 和发布前租约检查；未改动该测试断言或超时值。[独立安全复核](CR-WP07A_SECURITY_REVIEW.md)审查了最终音频变更和 API 启动重放竞态；动态范围、重跑结果与限制见[独立测试报告](CR-WP07A_TESTING_REPORT.md)及[机器可读测试证据](baseline/cr-wp07a-testing.json)。浏览器只使用合成账号和媒体。

## 冻结范围与旧实例

[SHA-256 清单](baseline/cr-wp07a-fingerprints.json)逐项记录本轮实际新增、修改及删除，并比对批准前端 10 个源文件、3 个构建文件、001～011 共 11 个迁移和历史资料。测试适配只让历史断言在专用隔离环境运行。本轮未执行 Git 操作。

最终清点保留实施前的 9 个容器和 13 个卷，9 个容器 ID 与启动时间相同。旧 manual 的 4 个容器仍处于停止状态。WP06 的 5 个容器冻结时运行，恢复工作时已观察为停止；本轮未对它们执行启停或清理。WP07-A 专用测试容器、网络和卷已回收，未发现正式候选项目资源。保留了镜像指纹和无内容证据。实测 API 和 Web 镜像已随合成资源回收；实测 PostgreSQL 和 RustFS 镜像仍在本机。正式创建前须按冻结版本重建、隔离复验并保留候选 API 和 Web 镜像。

路径 A 是首次部署。旧服务排空、旧授权关闭、旧凭据失权及旧数据迁移对新实例不适用，本轮未执行。历史 10 卷及 WP06 资源不作为数据来源；其内容和 BACKUP 不因名称或合成标签推断为空，继续隔离，归属、查看、迁移、恢复或删除另行审批。

## 正式准入与剩余审批

**隔离验证通过，建议下一阶段仅在单独获批后创建新的 CLOSED 实例。** 正式开放还需核对实际镜像、资源、门禁和巡检，并取得开放授权。若任一检查不符，保持关闭。

- 批准实际目标（建议 `vsa-local`、`127.0.0.1:58080`、新 `video_summary`、私有 `video-summary-private` 和五个独立命名卷）、实际端口、部署者、三种数据库凭据保管责任和应用 ADMIN 创建方式。
- 确认正式巡检通知渠道、接收责任人、启动方式和日志保留。正式配置使用批准镜像及实测 ID、独立秘密；不使用合成账号或测试配置。
- 单独批准创建。先启动 DB/RustFS、初始化并核对 001～011、角色权限和独立删除控制，然后启动 API/Worker，保持 CLOSED 且未发布 Web。待核对通过并获准后才发布本机 Web；再获准由维护身份开门。历史资源清理和真实模型接入分别审批。

失败时关闭新实例门禁并停止本机入口；门禁维护通道不可用时先停入口，再排空新 API/Worker。保留 DB、对象和控制卷；恢复后核对身份、删除意图与未完成清理再申请开放。只有兼容权限、迁移和控制格式且验证过的镜像才可回退。交接保存无用户内容的版本、权限、资源定位及诊断基线。

资源配置、故障恢复和历史卷清理边界见[全新本地部署方案](CR-WP07A_LOCAL_DEPLOYMENT_PLAN.md)。操作、权限及人工停点见[正式执行清单](CR-WP07A_FORMAL_RUNBOOK.md)，均未执行。
