## 3. 状态与重新启动

PowerShell在仓库根目录执行：

```powershell
Set-Location E:\GitHub\video-summary-app
python backend/tools/wp06_environment.py status --state '<验收临时目录>\state.json'
```

健康检查（仅检查本套合成API）：

```powershell
docker exec vsa-wp06-b44855a096-api python -m app.cleanup_ops health
```

如需查看删除作业，status必须带DELETE 202返回的作业id：`python -m app.cleanup_ops status --job-id UUID`，在上述合成API容器内执行；没有作业id时不猜测。

交付时首页、`/api/health/live`、`/api/health/ready`均200，cleanup health为healthy=true、persistent_faults=0。故障时记录现象给Main，不运行任意路径删除、批量数据库修复或正式迁移命令。

如环境已经停止，需要Docker Desktop、现有测试镜像及本机Python/Node依赖可用；只构建前端并新建专用环境：

```powershell
Set-Location E:\GitHub\video-summary-app\frontend
npm run build
Set-Location E:\GitHub\video-summary-app
python backend/tools/wp06_environment.py start
```

start输出新的UI地址、state路径、账号与合成样本；新端口替换本指南上述地址。默认生成新实例，不复用已停止的state。该工具使用已有本地测试镜像；缺少镜像或依赖时停止并报告，不读取业务.env，也不启动业务compose。保持MODEL_CALLS_ENABLED=false。

## 4. 清理本套环境

验收结束后执行：

```powershell
Set-Location E:\GitHub\video-summary-app
python backend/tools/wp06_environment.py stop --state '<验收临时目录>\state.json'
```

仅回收此state证明归属的容器、专用网络、主数据卷、合成媒体、日志和代理进程；保留stopped状态标记以便重复stop幂等。此操作会丢失这套合成任务、账号状态及样本，不能恢复；重新测试请start创建新实例。不要执行全局Docker清理。

本环境为验收而保留运行，未对外发布；未操作真实数据库、历史备份或模型API。人工结论由负责人填写，WP06验收后WP07仍需单独授权。
