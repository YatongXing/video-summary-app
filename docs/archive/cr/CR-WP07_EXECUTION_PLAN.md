## 3. 需要先补齐的切换条件

**G-01 持久维护门禁。** 当前缺实现，不得仅在控制卷放一个现有程序不读取的文件就宣布门禁生效。推荐复用独立控制位置的最小持久标志，维护通道设置/清除，普通API无操作入口；API启动/ready、内容及业务读写、流续传、Worker启动/领取/发布和必要I/O边界统一拒绝业务。运行中置位、重启仍关闭、控制失信拒读/不创建空控制、新旧进程及恢复中断须隔离验证。保留现有身份/意图/SH-EX/producer-ready，不新增授权epoch或管理员旁路。

如负责人选择部署层持久关闭入口并停服务替代，须另行接受其覆盖范围及证明重启不会自动对外开放、不会遗漏旧Worker/流/私有存储路径。此替代不默认获批。

**G-02 正式身份配置。** 分离PG初始化身份与API/Worker运行DSN，维护凭据不进入业务服务。运行角色非owner/NOSUPERUSER/NOCREATEDB/NOCREATEROLE/NOBYPASSRLS，无DDL、无维护角色继承/SET ROLE通道。维护角色兼schema owner及迁移/受控CLI，通常不需superuser；一次性基础设施管理权限单列。共享旧高权限角色不得直接全局NOLOGIN或撤权而误伤其他应用。

**G-03 可运行的最低故障发现。** 复用live/ready、worker进程状态、cleanup_ops health/status及持久告警。配置最多60秒一次的外部巡检（可30秒），覆盖缺失/超60秒进度、活跃I/O卡住、DB/S3不可用、清理BLOCKED/连续失败/超30分钟、暂存清理及Worker退出；明确接收人、观察渠道和处理职责。只写日志或存在CLI不算通知链落地。正式开放前需要非破坏故障验证及责任人实际收到/处理证据，S3-12不能推迟最低发现链。

上述补充代码/配置/巡检实施均需另授权；本次没有实施或安装任务。

## 4. 正式执行顺序（授权后逐关卡执行）

| 阶段 | 动作与退出证据 | 失败停留 |
|---|---|---|
| P0 发布冻结 | 核对已批准源码、dist、SQL SHA与发布镜像ID；包含untracked交付，配置模板无密钥，目标身份再次核实 | 不动目标，解释差异；不从HEAD猜版本 |
| P1 关闭入口 | 部署层先拒绝外部新请求并持久置维护状态，验证ready/业务请求拒绝；暂停新上传/排队/重试及处理领取 | 入口保持关闭 |
| P2 排空旧生产者 | 清点旧API/Worker、代理、连接池和进程树；受控停止业务进程及FFmpeg后代/在途流/清理I/O，检查FD/inode/SH-EX与旧DB连接 | 无停止证据不允许新物理清理；不杀无关实例 |
| P3 结构前检和迁移 | 维护身份只读核prefix/SHA/owner，确认完整有序已应用链；获批后仅应用冻结001～011缺失后缀 | 未知版本/checksum/不完整前缀保持维护，不补登记绕过 |
| P4 权限和历史授权终止 | 先证明新维护通道可重连，再配置运行角色、最小ACL；维护事务关闭实际旧purpose/support并撤销选定旧会话；旧服务凭据/连接失权核验 | 不复活旧授权，不丢维护通道，事务失败不开放 |
| P5 删除控制接管 | 保护现有独立journal并核DB身份/归属；在旧生产者实际排空证据后建立目标producer-ready；获批离线重放意图并核清理映射/状态 | 缺控制/身份不可信/未知生产者不重建空日志、不删未知资产 |
| P6 私有启动及验证 | 只启动批准版本和运行身份；门禁下先证拒绝；保持外部入口关闭，获批清应用门禁后通过受限维护网络执行合成smoke | 任一失败重新持久关闭并保持外部隔离，前滚修复 |

应用门禁拒绝业务时，不新增免门禁HTTP参数/管理员内容旁路来做smoke。私有验证期间外部入口仍关，标志清除和网络开放分为明确审批点。未获准前不在真实业务库创建/删除测试任务。

### 迁移条件与数据范围

- 001～011原文和校验冻结，010即使产品已退役仍作为兼容链保留；不跳010、不重排、不down-migrate或改schema_migrations SHA。
- 已应用001～011且SHA相同则无结构迁移动作；空的新目标需完整链；有业务表而无可信登记、未知高版本或非连续前缀时暂停，不当空库处理。
- run_migrations按每文件transaction/保存点运行，整体原子性取决于调用方；失败后读实际登记和提交边界再决定重放，不能假定整个批次全部回退。
- 011会把旧COMPLETED重置待核、接管旧RUNNING/MANUAL_REQUIRED并重登记相关资产，影响真实清理状态；须预先记录受影响无内容计数、原时间/次数/失败原因并授权，停止旧生产者后才执行。
- 默认只做批准结构及控制状态演进，不搬迁视频/摘要、不dump整库、不新建含内容快照。跨服务器/数据库内容搬迁另行提交方案和授权。

### 身份、关闭请求和失权

- 旧task_consents对runtime仅保留DELETE与清退所需task_id/user_id列读取，禁止purpose等授权字段读取及INSERT/UPDATE。
- support_requests禁止runtime创建新请求；保留legacy_support确需UPDATE(closed_at,close_reason)、SELECT(task_id,user_id,closed_at)及DELETE，按真实调用验证闭合，不能REVOKE ALL后破坏删除关闭/外键清退。维护身份可做一次性历史终止和受控恢复。
- 有实际旧授权才由维护事务关闭旧consent、未关闭support、推进原版本和最小审计；旧会话按批准范围撤销，用户重新登录，不要求重新授权排障。
- 已停止容器不等于凭据失效：核对旧角色/旧S3密钥所有使用者，先验证新维护/运行身份，再执行获批的NOLOGIN/轮换/定向撤权及旧连接终止；仅REVOKE CONNECT不等于终止现有连接。
- 连接终止按确认的目标DB/角色/连接PID精确执行，排除维护通道和其他业务，不全局终止PG。共享角色、PUBLIC/default grants、SECURITY DEFINER/search_path和membership/SET ROLE单独核对。
- 旧数据库/对象存储服务身份与网络均需隔离，避免旧binary不认识新门禁仍可重启。失权/关闭失败则不开放。首次空部署无旧身份，不执行虚构的失权或批量授权终止。

1. USER和ADMIN各自本人摘要中英文/JSON/视频Range及seek成功；任意他人ID含有效旧请求拒绝；停用/撤会话/角色变化/删除/到期/控制失信及流中变化停止后续发送。
2. 管理元数据顶层/嵌套均白名单，含本人无正文、文件名、对象地址或凭据；独立页面无上传/个人内容；任意字符串按Task ID字面匹配，%/_不是通配符，清空回默认页。编号仅任务名称下可复制。
3. 旧API/helper无owner回退，认证/角色/CSRF保持；应用管理员无DB/S3/维护秘密及代调用入口。
4. 当前版本身份、目录、桶/backend/key/version归属正确；旧COMPLETED不盲信。任务删除202仅接受，journal重放与实际对象/SQL/工作目录清理分层取证，N>=2删A不伤B、父死子活/FD/锁不退化。
5. 四态/job_version/退避/维护审计与CONFIG合法retry保持；BACKUP未批不删，未知位置不能靠重试猜目标。原30天内容和90天无内容审计义务不延长，未完成控制保留。
6. 旧服务/连接/凭据实际失权，运行角色负例和维护重连通过；持久门禁跨重启/故障拒绝，巡检渠道实际运行。仅live/ready200不足以证明清理无故障。

在专用合成环境复用已验收测试；目标上的写入/故障/重启/失权/删除验证必须按具体资源另批，不能拿测试隔离证据替代正式实证。真实模型仍禁用，质量/计费/2h2GB性能不作为本轮已证明能力。

## 6. 失败、重启与安全回退

- 迁移或权限配置失败：外部入口/持久门禁保持，重新查询实际已提交状态，只做经审兼容前滚；不得恢复旧purpose/排障服务。
- 旧角色失权后新运行失败：保留已验证维护通道修复，不重新启用旧服务秘密；先确认旧角色是否共享，防止误伤。
- 进程重启：先核维护标志、控制身份及结构；置位/未知则仍拒业务。只有同当前SQL、owner规则、删除控制兼容且已验证的旧镜像才允许回退，否则维持关闭。
- journal缺失/损坏/DB归属不符：不建立空卷绕过、不沿用历史producer-ready；保全当前独立控制并等待受控修复审批。
- 任何历史恢复另批：先离线隔离、保留当前控制、核快照时间/身份/删除证据，超90天或时间不可信不能靠工具强开；恢复后重放并终止旧新授权及会话，确认账户状态可信后才申请开放。
- 没有新增内容备份作为回退保证。软件可重部署不等于用户视频/摘要可恢复；已下载客户端副本也无法追回。

## 7. 历史未知资产与BACKUP

本机已记录的历史10卷保持原样；正式目标若涉及它们，先确认业务归属、对象版本/多段上传/工作目录/基础设施快照和副本。UNKNOWN/UNVERIFIED保持未知，不把验收库BACKUP=0外推到历史资源。
